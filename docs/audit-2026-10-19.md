# Pumpkin Panel — Full Codebase Audit (2026-10-19)

## Method and baseline

- Audited the working tree (`nightly`, commit `28ee481`) across backend (25.7k lines Rust),
  web (6.2k lines TS/TSX), 9 migrations, deploy, CI, tests, and all docs.
- Five independent deep dives: auth/API, runtime/lifecycle, files/backups/config/DB,
  web UI/integration, and deploy/docs/tests/code-quality.
- The highest-severity findings were then verified directly against the source.
- Baseline health: `make test` passes (229 tests, 3 ignored, web build OK), `oxlint` reports
  13 warnings / 0 errors, `npm audit --omit=dev` reports 0 vulnerabilities, Playwright e2e
  passes 6/6 locally with Docker.

**Verdict:** this is not a throwaway project. The core design (task persistence, readiness
truthfulness, path sandboxing, backup verification, migration integrity) is genuinely solid.
But it is **not yet safe to call real Minecraft hosting software**: a fresh rootful deployment
can produce unstartable servers, failed operations permanently wedge a server, there is no
reconciliation loop, and several archive/backup paths are unsafe. The previous AI also left
substantial dead code, duplicated mechanisms, misleading docs, and test fixtures that do not
exercise the production schema.

---

## What is genuinely solid (do not rewrite casually)

- **Task machinery:** single-statement CAS claim, interrupted-task requeue on boot, terminal
  state discipline, summary sanitisation and path redaction.
- **Readiness model:** `online` only after a real Minecraft status ping; stale/unavailable
  states are never presented as online.
- **Backup verification:** archive streamed to `.part`, SHA-256 computed, file re-read and
  re-verified before publishing the row; protected pre-restore backup; recovery copies kept.
- **Path sandbox:** lexical + canonical containment, dangling-symlink handling, `take(max+1)`
  read caps, symlink-free ancestor checks during extraction.
- **Migrations:** numbered, embedded with `sqlx::migrate!`, and migration 0008 is tested
  against a populated v7 database with `PRAGMA foreign_key_check`.
- **Auth fundamentals:** Argon2id, 256-bit opaque session tokens, only SHA-256 at rest,
  double-submit CSRF with constant-time compare, per-route permission layers, no CORS
  (same-origin by design), security headers + CSP.
- **Deployment posture:** digest-pinned base images and action SHAs, `cap_drop: ALL`,
  `no-new-privileges`, `su-exec` non-root runtime.
- **Honest limitations:** `docs/known-limitations.md` and the runtime compatibility matrix are
  candid and should stay that way.

## P0 — Critical (fix before calling this hosting software)

### P0-1. Tar hardlink traversal: arbitrary host file read/write
`crates/backend/src/file_service.rs:467-490` vs `:679-689`

`check_link_target` validates a hardlink target as if it were relative to the link's own
parent, but extraction creates the link with `dest_full.join(target)` (archive-root-relative).
A nested link name with a `..`-heavy target passes validation and escapes the server root.
Reachable from `POST /servers/:id/files/import` and from restore. Impact: read any host file
the manager can read (including the manager DB with password/session hashes) through
`GET /files/download`, and write through the planted link after a restore.

**Fix:** validate hardlink targets against the archive root; require the target to have been
extracted already; assert lexical containment before `hard_link`.

### P0-2. Archive import/export can exhaust manager memory
- Import accumulates every extracted payload in RAM before writing: `file_service.rs:559-604`,
  limit 10 GiB (`:52-58`). A small gzip bomb kills the process.
- Export builds the whole archive in a `Vec<u8>` with no cap: `file_service.rs:425-446`,
  `routes_files.rs:687-706`.
- `files/import` also reads the staged upload back into memory: `routes_files.rs:644`.

**Fix:** two-pass/streaming extraction with a running budget; stream export to a temp file
(`Body::from_stream`, as `download_backup` already does); use `import_tar_gz_reader` with a
file handle; enforce a max compression ratio and a smaller in-memory cap.

### P0-3. A failed start permanently wedges the server
`crates/backend/src/routes_servers.rs:865-873`, `:925-943`

`lifecycle_inner` writes `desired_state='running'` **before** enqueueing and never rolls it
back on task failure or enqueue failure. The idempotency check at `:867` then returns
`{"status":"already"}` and enqueues nothing. A crash/OOM, missing image, port conflict, or
failed create leaves the server impossible to start from the UI; only restart/update can
recover it.

**Fix:** only short-circuit when desired **and** observed agree; write `desired_state` on task
success (or restore the previous value on failure); add a regression test for start-failure →
start-again.

### P0-4. No desired-state reconciliation loop
`crates/backend/src/main.rs:676-685`, `runtime.rs:1081`, `routes_backup.rs:719-1040`

The only recurring loop runs scheduler + metrics. `sync_observed`/`reconcile` are boot-only or
read-only. Consequences: a crashed/OOM-killed world stays down (and no alert fires); a manager
crash during a `consistency="stopped"` backup leaves the world offline; a crash between image
swap and container create leaves `container_id=''` with no recreate path.

**Fix:** add a reconciliation pass every 60 s (desired running → start if exited/missing and
recreatable; desired stopped → stop if running), with per-server backoff; resume
`desired_state='running'` servers on boot; add `POST /servers/:id/recreate` or let start
recreate from the row.

### P0-5. Adjacent Bedrock port is not reserved in the database
`crates/backend/src/routes_servers.rs:186-200`, `:310-317`; `migrations/0008_integrity.sql:83`

The pre-check reserves `game_port` and `game_port+1`, but the only DB constraint is
`UNIQUE(game_port)`. Concurrent creates `25565` and `25566` both pass and produce overlapping
published ports; the second start fails with "port already allocated", which then triggers
P0-3. This is reachable with two users or two browser tabs.

**Fix:** a `server_port_reservations(port PRIMARY KEY, server_id)` table with two rows per
server, inserted in the same transaction; or unique indexes plus a trigger preventing
`bedrock_port == another.game_port`.

### P0-6. Child data directory is never chowned to the runtime user
`crates/backend/src/runtime.rs:784-800`, `:404-418`

The manager (normally root, because it mounts the Docker socket) creates
`<data_root>/<uuid>` as `root:root 0755`. The Pumpkin image runs as UID 2613 (or the configured
`PUMPKIN_RUNTIME_USER`, `100:101` in the shipped image) and cannot write its world/config;
the container starts and exits. `tests_docker.rs` works around this with a manual
`chown -R 2613:2613`, which proves the production path lacks it.

**Fix:** `std::os::unix::fs::chown` the leaf to the configured runtime user after
`create_dir_all`, `chmod 0750`, and fail create loudly if it fails; default the container
`User` to the manager's uid/gid when no override is configured.

### P0-7. Delete/remove force-kills a running world
`crates/backend/src/runtime.rs:861-870`, `routes_servers.rs:792-810`, `task_runner.rs:566-571`

`RemoveContainerOptions { force: true }` sends SIGKILL. Neither delete nor the remove task
stops first, despite the documented 35 s graceful stop for world flushing. This can corrupt a
live world and definitely skips the save.

**Fix:** inspect → SIGTERM + 35 s → remove, shared by both call sites; preferably make delete a
persisted task.

### P0-8. Fresh deployment image build is broken by host `node_modules`
`deploy/Dockerfile:11` (no `.dockerignore` in the repo)

`COPY apps/web/ ./` overwrites the musl-native modules installed by `npm ci` with the host's
glibc `node_modules` and stale `dist`, recreating the `lightningcss` failure the previous line
was written to avoid. `target/` (9,994 files) is also uploaded as build context every time.

**Fix:** add **Critical** `.dockerignore` (`target/`, `**/node_modules/`, `apps/web/dist/`,
`.git/`, `.opencode/`, `dev.db`, `dev-data/`, `.env`, test/playwright output) and narrow the
COPY to source files.

### P0-9. Shipped `.env` breaks login over plain HTTP
`deploy/.env:10` (`PUMPKIN_INSECURE_COOKIES=0`) vs `deploy/.env.example:15` and
`deploy/docker-compose.yml:33` (default `1`).

With `0`, the session cookie is `Secure` + HSTS is sent, so a browser on
`http://<lan-ip>:8080` silently refuses to send `pm_session`; login appears to succeed and
every subsequent request is 401. `.env` also sets `BACKUP_DIR`/`DATABASE_URL`, which
`docker-compose.yml` overrides anyway (dead, misleading config).

**Fix:** delete the untracked `deploy/.env` or make it identical to `.env.example`; remove the
overridden keys; document that `environment:` beats `env_file:`.

### P0-10. Rate limiter is bypassed by a new TCP connection per attempt
`crates/backend/src/routes_auth.rs:571-576`

`format!("ip:{addr}")` renders `SocketAddr` as `ip:port`, so each connection gets a fresh
bucket. Per-IP throttling effectively does not exist; only per-username throttling remains.
Tests miss it because `axum_test` supplies no `ConnectInfo` and always hits `ip:global`.

**Fix:** `format!("ip:{}", addr.ip())`; add a regression test with two ports for the same IP.

### P0-11. Manager DB restore is unusable in practice
`crates/backend/src/main.rs:449-452`, `:458-462`; `routes_admin.rs:833-873`

`POST /admin/database/restore` is on the 5 MiB `protected` router, and multipart applies its own
2 MiB limit; any real DB (audit + metrics) exceeds that. The handler's 1 GiB check is dead.
It also buffers the upload and leaves WAL sidecars behind on the boot swap
(`main.rs:581-596`), so the restored DB can replay the old WAL or be corrupted.

**Fix:** move the route to the upload router (`DefaultBodyLimit::disable()` + 1 GiB layer),
stream to a temp file, and on swap remove `-wal`/`-shm`, fsync, then rename; use one
pre-restore snapshot function (`VACUUM INTO`) for both paths.

### P0-12. `/health/ready` always returns ready
`crates/backend/src/main.rs:489-494`

`db_ok: true` is a literal and `docker_ok` is a boot-time snapshot. The manager reports
`{"status":"ready"}` with a deleted/corrupt/locked DB or a dead Docker daemon, so orchestration
never restarts it. The Dockerfile healthcheck also uses `/live`.

**Fix:** probe the DB with `SELECT 1` (timeout) and Docker with a cached last-success
timestamp per request; point HEALTHCHECK at `/ready` (with `start-period`).

### P0-13. Backup retention can delete files outside the backup directory
`crates/backend/src/routes_backup.rs:877-903`, `:1741`, `:1850-1852`

`backups.storage_path` is free-text with no constraint and can be replaced wholesale by a
manager-DB restore. Prune/delete/download trust it, so a tampered/restored row can unlink or
serve an arbitrary host path (e.g. `/data/pumpkin-manager.db`, a server's `level.dat`).

**Fix:** validate `storage_path` canonicalises under `backup_dir` and matches `<id>.tar.gz`
before any unlink/serve; delete the row first in a transaction, then unlink.

### P0-14. Authenticated file writes can plant a symlink/Hardlink host compromise
Beyond P0-1, the config editor bypasses the sandbox:
`crates/backend/src/routes_config.rs:110-112`, `:548-575`

`config_path` joins `server.data_path` with no `resolve()`. A `pumpkin.toml` symlink turns
`GET /config` into an arbitrary host file read; an empty/relative `data_path` resolves to the
manager's CWD for both read and write.

**Fix:** resolve through `file_service::resolve` (or `symlink_metadata` + reject symlinks) and
use the same `data_path`-or-`server_root/id` fallback as `routes_files`.

### P0-15. Web UI ignores permissions; viewers see broken controls
`apps/web/src` (ServerDetail, Backups, Config, Files) vs `crates/backend/src/auth.rs:159-172`

Viewer accounts get only read permissions, but every mutating control renders enabled. A
viewer clicking start/backup/save/upload receives `403 PERMISSION_DENIED` and the UI presents
it as a generic failure. Meanwhile `admin` is treated as owner (`apps/web/src/lib/admin.ts:44`)
and can open Users/Settings, which the backend reserves for owner.

**Fix:** expose the effective permission set from `/auth/me` (or a permissions endpoint) and a
`useCan(...)` helper; gate controls with disabled + explanation; split `RequireOwner` vs
`RequireAdmin` and correct the denial copy. Add e2e coverage for both roles.

## P1 — High (major reliability/security/UX)

### Backend / security
1. **No authentication audit trail** — `routes_auth.rs` never calls `audit::record`; login
   success/failure, setup, logout, password change, rate-limit rejections and 401/403 are
   invisible. `docs/security.md:10` claims otherwise.
2. **`update_user` swallows DB errors** and audits `ok` regardless — `routes_admin.rs:223-259`.
   A failed update returns `{ok:true}` and a false audit row; the two updates are not
   transactional.
3. **Last-owner guard is TOCTOU** — `routes_admin.rs:205-228`, `:389-404`. Two concurrent
   demotions/deletions can leave zero active owners, permanently bricking administration.
4. **Login username enumeration + timing mismatch** — `routes_auth.rs:261-264` returns
   `403 ACCOUNT_DISABLED` before Argon2 work, while unknown users get a 401 after dummy work.
5. **Manager DB snapshot is world-readable in `/tmp`** — `routes_admin.rs:777-802`
   (`VACUUM INTO` with umask), left behind on crash; contains hashes and the audit trail.
6. **No Host validation** — `routes_auth.rs:524-553` trusts the request's own `Host` for
   same-origin, enabling DNS rebinding against unauthenticated `POST /auth/setup`.
7. **`Secure` cookie derived from client headers** — `routes_auth.rs:486-507` honours
   attacker-supplied `Origin`/`X-Forwarded-Proto` with no trusted-proxy gate.
8. **`create_user` accepts credentials `login` rejects** — `routes_admin.rs:279-293` vs
   `routes_auth.rs:31-33`, `:627-643` (no username/password bounds).
9. **Session table grows forever** — no idle timeout, no pruning, no revocation UI;
   `main.rs:678-685` never deletes expired sessions/audit rows (`auth.rs:447-470`).
10. **Stateless alerts and readiness lie** — see P0-12; also `unverified-image` fires for every
    server because it checks `image_reference.contains("@sha256:")` while the digest lives in
    `image_digest` (`routes_metrics.rs:146`).
11. **`is_daemon_down` string matching** duplicated 3× misclassifies permission errors as
    `RUNTIME_UNAVAILABLE` (`routes_servers.rs:210`, `routes_backup.rs:614`,
    `update_service.rs:369`).
12. **`error.rs` is dead code**; extractor/layer rejections bypass the JSON error envelope;
    request IDs are minted per audit row instead of propagated.

### Runtime / lifecycle
13. **Update readiness pings `127.0.0.1`** and gives up after 20 s (`update_service.rs:732-770`,
    `:43-47`), so IP-bound servers and large worlds always "fail" and auto-rollback. Same
    hardcode in `metrics_collector.rs:135` and `routes_servers.rs:1003`.
14. **Rollback target digest is erased** — `update_service.rs:1273-1281`, `:719-739`: an
    unpinned update writes `image_digest=''`, so rollback restores a mutable tag, not the image
    that ran. Nothing resolves tag → digest.
15. **Cancellation is unreachable** — nothing ever writes `cancel_requested`;
    `routes_admin.rs:88-104` refuses to cancel running tasks, and every cooperative checkpoint
    in `routes_backup.rs` is dead code.
16. **Scheduler/metrics loop is unsupervisored and unbounded** — `main.rs:676-685`: one panic
    kills all schedules and metrics permanently; `sample_all` is serial with 2 s pings and can
    exceed 60 s; `interval` uses `Burst`, so it free-runs after an overrun.
17. **Scheduler bypasses the task runner and op locks** — `scheduler.rs:965-1002`, `:1116`:
    restarts run inline (up to 35 s), `delete_server` can race a scheduled backup/restart, and
    a scheduled restart on a stopped server starts it while leaving `desired_state='stopped'`.
18. **Backup semaphore is global and `SERVER_BUSY` skips are not retried** —
    `routes_backup.rs:584-588`, `:1435`, `:1500`; one backup at a time cluster-wide.
19. **Update's "protected pre-update backup" is a live tar** — `update_service.rs:1180-1200`
    (`adapter: None`, `"live"`), then the container is stopped only later.
20. **Update `container_id` writes are error-swallowed** — `routes_servers.rs:464-473`,
    `update_service.rs:317-330`, plus create-failure cleanup does not remove an orphaned
    container. Recovery requires update/rollback.
21. **Metrics CPU/memory are wrong** — one-shot stats + empty `precpu_stats` produce a
    lifetime average, not current CPU (`runtime.rs:978-1035`); memory includes page cache and
    looks permanently pegged (`runtime.rs:1036`).
22. **7-day metrics retention is actually ~34 server-days total** — 50k global row cap
    (`metrics_collector.rs:14-16`, `:151-166`); the 60 s prune full-scans and re-sorts every
    minute.
23. **Boot with Docker down records every server as `missing`** — `metrics_collector.rs:96-113`
    conflates "daemon unreachable" with "container deleted", polluting history.
24. **No graceful manager shutdown** — `main.rs:706-716`: no SIGTERM drain; interrupted
    operations rely on requeue/fail.
25. **Four lock implementations; two leak on cancellation/panic** —
    `op_lock.rs` (correct), `routes_config.rs:412-421`, `update_service.rs:354-386`
    (`WORKER_LOCKS` is a separate global set). One aborted config save bricks lifecycle,
    backup, restore and delete for that server until restart.

### Files / backups / config / data
26. **Backup completion update ignores errors** — `routes_backup.rs:781-792`: a failed UPDATE
    leaves a verified archive stuck `in_progress`, invisible to retention, and the task still
    reports success.
27. **Import is destructive on failure with no rollback** — `file_service.rs:645-676` removes
    existing entries before writing; ENOSPC mid-import corrupts the data dir.
28. **Backup/export/import are not round-trippable** — backups drop symlinks
    (`backup_service.rs:313-331`), exports keep them, importer rejects them; tar modes are
    ignored; export→import fails for legitimate container symlinks.
29. **Restore swap has a crash window** — `routes_backup.rs:1363-1394`: three renames; a crash
    after the first leaves the data dir absent, and the next start silently creates a fresh
    world; nothing marks the server inconsistent.
30. **`retention_count=0` deletes all but one backup** — `scheduler.rs:263-268`,
    `routes_backup.rs:838`, `backup_service.rs:83-138`; no DB CHECK.
31. **Completed restore/backup rows are not fsynced** — `backup_service.rs:238-267`,
    `routes_backup.rs:767-769`: a power loss can publish a truncated "verified" archive.
32. **Live backup aborts on files vanishing mid-walk** — `backup_service.rs:250-255`;
    consistent only for stopped worlds, which is not documented for world data.
33. **Staged import/upload ignores ownership** — after restore, files are manager-owned; any
    deployment not using the shipped entrypoint leaves the container unable to write.
34. **Config `COMMIT` failure is swallowed** — `routes_config.rs:611-620`: returns `200` with a
    revision that the DB rolled back, permanently diverging the file from its baseline.
35. **Config write has no fsync** — `routes_config.rs:557-575`; crash can produce a truncated
    `pumpkin.toml`.
36. **Config revisions are off by one and can revert to empty** — `routes_config.rs:513-545`,
    `:370-395`: the newest revision is not revertible; a first save with no existing file
    records empty content and reverting writes an empty config.
37. **`docs/backup-restore.md` / `docs/api.md` overclaim** — newer-DB rejection is inert
    (`user_version` always 0), restore upload cap, missing world-backup documentation,
    `PATCH /servers/:id` documented but not registered.

### Web
38. **Config save sends a stale revision** — `Config.tsx:206-207`; a second save before the

39. **409 on update is always reported as "no verified backup"** — `ServerDetail.tsx:135-146`;

40. **Role editor wedges on "saving…" after a failed PATCH** — `Users.tsx:47`, `:57-79`;

41. **Query cache survives logout/401** — `auth.tsx:188-216` removes only `auth/me`; the next

    (`Overview.tsx:115`), console permanently shows "Failed to load logs." (404)

47. **One shared `retainData` checkbox for every row** — `Servers.tsx:31`, `:109`: unchecking

48. **Restore gate uses the wrong state** — `Backups.tsx:43`, `:414` gates on cached

49. **Backup mode silently stops a running server** — `Backups.tsx:45` defaults to

50. **Name validation contradicts the backend** — `servers.ts:137-149` rejects valid names and

51. **TypeScript `strict` is off** — `tsconfig.app.json`: `strictNullChecks` unverified, while
    `Monitoring.tsx:361` / `Overview.tsx:198` dereference `cpu_percent` that can legitimately
    be `null` (`metrics.rs:93-99`) — a white-screen path.
52. **No error boundary; no skip link** — a single render throw blanks the panel.

### Deploy / CI / tests
53. **Image built with Rust 1.90, dev/CI/test use 1.99** — `deploy/Dockerfile:16` vs

54. **CI runs tests in parallel while `make test` requires `--test-threads=1`** —

## P2 — Medium (selected; see per-area notes for the rest)

- **Auth/API:** manager DB restore route on wrong router; no `Cache-Control: no-store`/COOP on
  API; password policy length-only and change-password unthrottled; `metrics_interval_seconds`
  is a dead knob; `bind_addr` hardcoded `0.0.0.0`; public unthrottled `setup-status`;
  `/api` (no slash) falls through to SPA; viewer DTO leaks `data_path`/`container_id`;
  bearer scheme is case-sensitive; no `WWW-Authenticate`; no idle session timeout.
- **Runtime:** per-server metrics cap needed; `prune_samples` full scan; readiness hardcodes
  protocol 767 and `127.0.0.1`; preview vs worker disagree on `verified`/`in_progress`;
  `unverified-image` alert; `create_server` pulls synchronously with no timeout; no image GC;
  `server_status` writes on a read path without `updated_at`; scheduled restart can start a
  stopped server; scheduler has no op lock; inline Docker in tick loop; update worker op-locks
  leak on panic; update backup dir re-reads env; rollback has no pre-rollback backup.
- **Files/backups/config:** TOCTOU on non-existent path tails; escaping symlinks cannot be
  deleted/renamed; no filename control/bidi sanitisation and no upload part cap; client archive
  errors map to 500; import checks `desired_state` but not observed state; no op lock on file
  mutations; config lock leak; config fsync/COMMIT; revision retention unbounded; archive modes
  not applied; preflight restore space underestimates; `.part` archives not swept; backups
  survive server deletion; no DB CHECK constraints; 0008 relies on sqlx transaction wrapping;
  no explicit WAL/busy_timeout/synchronous/pragma policy and DB file mode.
- **Web:** Settings page is only a DB download/stage; capabilities endpoint ignored; no task
  cancellation; "Save rejected (422)" for every error; import/upload overwrite without
  confirmation; Files page promises an editor it lacks; audit search only filters the page;
  unsaved config edits can be lost; raw `<a href>` triggers full reloads; active tab hardcoded;
  charts hardcode dark hex; charts not accessible; aria-label ≠ visible label (Login/Setup);
  mobile drawer not keyboard-modal; shell version hardcoded; connect address guessed;
  no query defaults and per-server fan-out; guided TOML silently drops invalid input;
  staged-restore state sticky; e2e hard-asserts exactly two cookies and uses ambiguous
