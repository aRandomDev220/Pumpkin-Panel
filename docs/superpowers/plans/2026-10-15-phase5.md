# Phase 5 (Backups + Restore) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Safe full-data backups (manual + scheduled) with checksums, retention floors, and a recoverable restore flow that never loses the only good copy.

**Architecture:** Full data-dir tar.gz snapshots (never guessed file lists) with SHA-256 checksums verified by re-listing. Backup/restore run as task rows executed by a semaphore-gated (concurrency 1) worker inside the routes module — no `main.rs` changes needed. Retention deletes only after success, never the last verified or protected backup. Restore requires stopped, auto-creates a protected pre-restore backup, and keeps a recovery copy until success.

**Tech Stack:** Rust Axum + `tar 0.4` / `flate2 1` (have), `cron 0.12.1` (new), `sha2` (have); React 19 + TanStack Query frontend.

**Spec:** `pumpkin-manager-implementation-plan.md` (§15 Backups, §17.5, §19 scheduling, §8.6/§8.7 tables); trust boundaries §5.3/§12.

## Global Constraints

- Rust edition 2021; `cargo fmt --check` clean; `cargo clippy -p pumpkin-manager-backend --all-targets -- -D warnings` clean (documented `allow`s only).
- TypeScript strict; no `any`; `npm run build --prefix apps/web` clean.
- TDD: failing test first, watched fail, minimal code, full-suite green.
- Deps pre-added (`cron` workspace + crate); stubs + `mod` lines pre-wired in BASE — implementers NEVER edit `Cargo.toml`, `main.rs`, or another task's files. Task 2 alone creates `migrations/0004_backups.sql`.
- SQL only via bind parameters. Never log archive contents or checksums-adjacent secrets (checksums themselves are fine to store/display).
- Commit ONLY the task's own files; `feat:` prefix. No-subagents contract.
- `main.rs` route wiring + boot calls (`startup_cleanup`, scheduler spawn) are the controller's job — Task 2/3 expose `pub` entry points; handlers are standalone `pub async fn` taking `State<AppState>`.

## Review Focus

- Pre-restore backup FAILS (disk full, daemon gone) and restore proceeds anyway, wiping the only copy (Task 2 owns: test aborts restore when the safety backup fails).
- Restoring another server's backup into this server (ownership check missing → cross-server overwrite) (Task 2 owns: test).
- Retention prune racing a running backup deletes the in-flight artifact or its row (Task 3 owns: test — prune touches only `completed` rows, never in-progress).
- Checksum mismatch on restore/download is silently ignored (Task 2 owns: test pins `BACKUP_CORRUPT`).
- Stopped-server requirement bypassed via direct `/backups/:id/restore` on a running server (Task 2 owns: test pins 409).
