# Phase 6 (Monitoring + Automation) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Persisted metrics with bounded retention, truthful alerts, scheduled restarts, and a redacted diagnostics export — finishing the observable control plane.

**Architecture:** A new `metrics_collector` module samples every server each tick (Docker stats + protocol ping + restart count) into `metrics_samples`, pruned to a 7-day / 50k-row bound. Alerts derive statelessly on read (never stored, never stale). Scheduled restarts reuse the existing task + runner path via a new `scheduled_tasks` table handled in the scheduler tick. Diagnostics assemble redacted facts on demand.

**Tech Stack:** Rust Axum + existing `sysinfo`/`bollard`/`cron`; React 19 + TanStack Query frontend. No new dependencies.

**Spec:** `pumpkin-manager-implementation-plan.md` (§16 Monitoring, §19 scheduling, §21 observability, §8.10 metrics); trust boundaries §5.3/§12.

## Global Constraints

- Rust edition 2021; `cargo fmt --check` clean; `cargo clippy -p pumpkin-manager-backend --all-targets -- -D warnings` clean (documented `allow`s only).
- TypeScript strict; no `any`; `npm run build --prefix apps/web` clean.
- TDD: failing test first, watched fail, minimal code, full-suite green.
- Stubs + `mod` lines for `metrics_collector.rs` / `routes_metrics.rs` pre-wired in BASE — implementers NEVER edit `Cargo.toml`, or another task's files. Task 1 alone creates `migrations/0006_metrics.sql`. Task 3 may edit `scheduler.rs` + `routes_admin.rs`; Task 1 may edit `runtime.rs` (restart_count only).
- Unsupported/unavailable metrics are explicit `null`, never zero. No secrets in diagnostics (no tokens, passwords, env dumps, file contents).
- Commit ONLY the task's own files; `feat:` prefix. No-subagents contract.
- `main.rs` route wiring + collector/tick loops are the controller's job — handlers are standalone `pub async fn` taking `State<AppState>`.

## Review Focus

- A dead/stopped server's samples showing `0` CPU that reads as "idle" instead of "not running" (Task 1 owns: test pins nulls + state).
- Alert flapping on a single failed ping (Task 2 owns: test — one failed ping does not alert; sustained failure does).
- Scheduler double-firing a restart after manager reboot (Task 3 owns: test — reboot with overdue task runs once, recomputes next_run, no duplicate).
- Diagnostics leaking a session token or password hash (Task 3 owns: test scans output for planted secrets).
- History endpoint returning unbounded rows for a year-old server (Task 2 owns: test pins the row cap).
