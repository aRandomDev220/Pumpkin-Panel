# Test-Gaps Closure Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Close the three highest-value test gaps (E2E, daemon-backed dispatch, concurrency) with automated suites that run green locally and in CI.

**Architecture:** Three file-disjoint suites: Playwright browser E2E under `apps/web/e2e/`; ignored-by-default daemon dispatch tests in `crates/backend/src/tests_docker.rs`; concurrency tests in `crates/backend/src/tests_concurrency.rs`. Mod lines for both Rust files are pre-wired in `main.rs` — implementers create files only.

**Tech Stack:** Playwright + TypeScript (web), Rust `#[tokio::test]` + `axum-test` (backend), Docker daemon + `ghcr.io/pumpkin-mc/pumpkin:master` (live).

**Spec:** `pumpkin-manager-implementation-plan.md` (§22 Testing Strategy, §25 Phases 2–3 exit criteria, §26 Definition of Done); contracts in `docs/phase2.md` (API table) and `docs/phase3.md` (contracts section).

## Global Constraints

- Rust edition 2021; `cargo fmt --check` clean; `cargo clippy -p pumpkin-manager-backend --all-targets -- -D warnings` clean (documented `allow`s only).
- TypeScript strict; no `any`; `npm run build --prefix apps/web` clean.
- TDD: every step writes the failing test/command first, watches it fail, then implements.
- Backend dev ports must not collide: E2E uses API port `18091`, game ports `26565+`.
- E2E servers named `e2e-*`; E2E cleans up every container + data dir it creates, even on failure (afterEach/afterAll).
- Never commit secrets; test passwords are literals like `e2e-owner-secret1` (not real credentials).
- Commit ONLY the task's own files (`git add <exact paths>`, never `git add -A`); commit message prefix `test:`.
- No-subagents contract: implementers never dispatch subagents or reviewers.
- Do not edit `crates/backend/src/main.rs` (mod lines pre-wired), `docs/phase2.md`, `docs/phase3.md`, or another task's files.

## Review Focus

- E2E sleeps/poll timeouts flaky on slow CI (task owns: poll-until-terminal helpers with generous deadlines + container log dump on failure).
- Daemon tests assuming local Docker socket/image (task owns: skip gracefully when socket missing, pull-if-absent documented).
- Data-dir UID trap: manager-created dirs are unreadable by Pumpkin (2613) (task owns: E2E chowns leaf dirs via `docker run --rm -v … alpine chown`, exactly like docs/phase3.md; never the servers root).
- Playwright browser download in CI (task owns: `npx playwright install --with-deps chromium` step in the new CI job).
- A passing test that asserts nothing (reviewer checks every assertion pins a contract value).

## File Structure

- Task 1 creates: `apps/web/playwright.config.ts`, `apps/web/e2e/lifecycle.spec.ts`, `apps/web/e2e/helpers.ts`; modifies: `apps/web/package.json` (devDeps `@playwright/test`, script `test:e2e`), `.github/workflows/ci.yml` (new `e2e` job).
- Task 2 creates: `crates/backend/src/tests_docker.rs` (all `#[ignore]`d except pure-mapping tests).
- Task 3 creates: `crates/backend/src/tests_concurrency.rs`.

### Task 3: Concurrency tests (races that must fail safe)

**Files:**
- Create: `crates/backend/src/tests_concurrency.rs`
- Test: `cargo test -p pumpkin-manager-backend concurrency_`

**Interfaces:**
- Consumes: `build_router`, `AppState::for_tests`, `axum-test` patterns from `tests_phase2.rs`.
- Produces: nothing downstream (leaf task).

- [ ] **Step 1: Write failing tests in `crates/backend/src/tests_concurrency.rs`** — (a) `concurrent_duplicate_create_fails_safe`: 8 concurrent `POST /servers` (same name `race-srv`, same game_port `26580`) → exactly one `201`, rest `409` (`SERVER_CONFLICT` or `PORT_UNAVAILABLE`), and `GET /servers` total `== 1`; (b) `sequential_busy_rejects_second_op`: insert `queued` task row for a server with container set, `POST start` → rejected with no new task row; expected code is environment-dependent — `409 SERVER_BUSY` with a runtime attached, `503 RUNTIME_UNAVAILABLE` without one (adapter check precedes the busy check; fail-safe holds either way — pin what the environment yields and document why); (c) `concurrent_starts_without_runtime_stay_clean`: 6 concurrent `POST start` on a containerless server → all `409 MISSING_CONTAINER`, zero task rows created. Name every test `concurrency_*`.

- [ ] **Step 3: Implement to GREEN** — tests are black-box against the router; production code already guards, so GREEN means proving it. If any test exposes a real race (e.g. two `201`s), STOP, report `BLOCKED` with evidence — do not redesign locking yourself.
- [ ] **Step 4: Full suite stays green** — `cargo test -p pumpkin-manager-backend`. Expected: all pass.
- [ ] **Step 5: Commit** — `git add crates/backend/src/tests_concurrency.rs` + `git commit -m "test: concurrency fail-safe tests"`.
