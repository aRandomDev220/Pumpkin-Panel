- Communicates in terse, lowercase messages (often with typos, sometimes just two-word imperatives like "commit and push", "ok goahed with phase 3") and delegates the whole investigation-to-fix loop, expecting the agent to dig through CI logs/tooling, decide branch/message/scope itself, and report findings without step-by-step hand-holding. - Prefers the agent to keep executing without waiting for approval — a short "go ahead and fix the next thing" or "fix everything" means audit the repo, fix, commit, push, and continue through the remaining queue rather than pausing at confirmation prompts or asking clarifying questions. Confidence: 0.7
- Gives broad, open-ended mandates ("fix everything, make it function like a real …") and judges the result on whether it actually works end-to-end like the real-world product, not on partial or cosmetic progress. Confidence: 0.55
- Expects code left behind by other AI models to be cleaned up as part of the job, not just extended or worked around ("the previous ai gent just messed up the ui" → wants it overhauled, not patched). Confidence: 0.6
- Works in agreed phases: approves a prioritized remediation plan with a short signal ("ya strart with phase 0", "ok go ahead with phase 1.", "ok goahed with phase 3", "ok goahead with next phase") and expects that entire tranche to be executed end-to-end — every item fixed, tested, committed separately, pushed, and reported — before moving on to the next phase, without re-confirming each step inside the phase. Confidence: 0.8
- Asks for maximum depth ("full audit of the code base, everything in detail") and expects exhaustive, evidence-backed findings — concrete file:line references, severity ranking, and a prioritized remediation order — not a shallow summary or a list of style opinions. Confidence: 0.65
- Judges UI against real, existing products rather than invented design: wants screens to look like how established domain software actually looks (e.g. real Minecraft hosting panels) and to be visually faithful to a named reference site's design system (tokens, type, geometry), pulled from the live source rather than approximated. Confidence: 0.7
- For large redesigns, prefers a deep audit and a written plan ("deep audit and plan out") before any code is changed. Confidence: 0.65
- Expects the agent to proactively find and use whatever installed skills/workflows apply ("look for any skills that will help you") rather than improvising an approach — e.g. loading plan-execution, test-driven-development, and verification-before-completion skills for a phased implementation.
